# 附件与本机媒体

要让 Claude 读取文件，把文件放在当前 Windows 项目中，在聊天里给出相对路径。桥接根据文件类型和权限决定如何处理。

## 文件类型处理

| 类型 | 桥接行为 |
| --- | --- |
| **文本或代码** | 通过工作区工具读取内容。 |
| **图片和 PDF** | `windows-workspace media` 按原始字节导出到 VPS 会话缓存，单文件上限 5 MiB。Claude 用原生 Read 查看缓存。 |
| **视频** | 返回 Windows 文件路径和大小。需要抽帧或转码时由 Claude 使用本机程序。 |
| **宿主内联图片** | CodexHost 以 32 MiB 为本机接收上限，远端传输另受 5 MiB 约束。 |

## T3 Code 拖入或粘贴

T3 需要给 Shim 提供可读的附件路径。默认 T3 附件目录和显式配置的额外目录可用。临时文件过期或超限时，先把文件保存到项目，再让 Claude 读取。

Shim 在受支持的 Read 调用和审批事件中，把 `.bridge-media` 缓存路径映射回 Windows 原始路径。客户端预览需要本机文件仍存在。

## CodexHost 附件

插件读取公开接口提供的结构化附件，也支持解析约定的 Desktop 文本附件清单。超出媒体上限的文件携带路径和大小进入上下文，Claude 再决定处理方式。

## 缓存

导出后，远端会话可按原生文件路径读取缓存。再次请求时，Windows 重新检查授权和内容哈希，远端校验完整性。图片打不开时，核对：文件大小、源文件是否还在、模型是否收到附件、客户端能否渲染预览。
